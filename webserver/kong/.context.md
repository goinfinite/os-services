Kong Gateway (Enterprise 3.13) as an Infinite OS installable service. Database-backed: the install chain creates a dedicated PostgreSQL instance and user through Infinite OS CLI commands before bootstrapping Kong migrations.

## Summary

- manifest.yml — v1 manifest (`nature: solo`, `type: webserver`, ports 8000/http + 8443/https): installs postgresql via `os services create-installable`, Kong apt repo + `kong-enterprise-edition=3.13.0.0`, `os db create`/`create-user` for the `kong` database, applies schema grants, copies assets, bootstraps migrations; uninstall reverses each step
- assets/kong.conf — Kong config template (postgres datastore on 127.0.0.1:5432); `kong_password` placeholder is sed-replaced with `%randomPassword%` at install
- assets/kong_supervised.sh — startCmd wrapper: `kong start`, traps SIGINT/TERM/QUIT to `kong stop`, polls `kong health` every 30s and exits 1 on unhealthy so the OS restarts the service
- assets/kong_user_privileges.sql — grants `kong_user` USAGE/CREATE on the public schema (run as postgres via psql during install)
- assets/avatar.png — service icon

## Constraints

- MUST NOT remove the `os db create`/`create-user` steps or their uninstall counterparts — Kong has no DB-less mode in this manifest and orphaned databases/users leak.
- The health-poll exit-1 behavior in kong_supervised.sh is the restart trigger for the OS supervisor; MUST NOT swallow it.

## Guidance

- Keep the `%randomPassword%` placeholder name in kong.conf consistent with the install sed (`s|kong_password|%randomPassword%|g`).
- The install refreshes the apt index inline (`apt-get -qqy update && install_packages -qqy kong-enterprise-edition=3.13.0.0`) instead of the standalone `apt-get update -qq` step the catalog uses after adding an apt source. The index is still refreshed before the install.
