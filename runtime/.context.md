Language runtime services for executing applications. Each subdirectory is one installable runtime with a manifest and assets. The version-managed runtimes (Bun, Java, Node, Python, Ruby) are `nature: multi` and install via mise; PHP WebServer is `nature: solo` and installs OpenLiteSpeed via a shell script.

## Summary

- bun/ — Bun 1.0–1.2 (manifest.yml, assets/avatar.png): `mise install bun@%version%`, seeds a starter `/app/html/index.tsx` (Bun.serve on port 3000)
- java/ — Java (manifest.yaml, assets/avatar.jpg): mise-provided distributions (openjdk, temurin, zulu, corretto, graalvm, liberica, sapmachine, ...); seeds a starter `/app/genericStartupFile.java` HTTP server on 8080
- node/ — Node 4–25 (manifest.yml, assets/avatar.jpg): `mise install node@%version%`, seeds a starter `/app/html/index.js` on port 3000, runs as `nobody`
- php-webserver/ — OpenLiteSpeed + PHP 5.6–8.5 (manifest.yml, assets/): the full web+PHP stack; see its assets below
- python/ — Python 2.7–3.13 (manifest.yaml, assets/avatar.png): mise install with build deps, seeds a py2/py3-compatible starter `/app/genericStartupFile.py` HTTP server on 8000
- ruby/ — Ruby 1.8–4.0 (manifest.yaml, assets/avatar.png): mise install with build deps + webrick gem, seeds a WEBrick starter `/app/genericStartupFile.rb` on port 3000

## Constraints

- Each runtime MUST have a manifest file defining installation steps.
- Runtimes marked `nature: multi` support multiple versions installed simultaneously (version selection via `mise x <rt>@%version%` in startCmd).
- php-webserver install steps MUST pass version, `%primaryHostname%`, and `%installableServiceAssetsDirPath%` to `assets/install.sh`, which only accepts versions mappable to the `latest`/`legacy` channel.

## Guidance

- Starter startup files SHOULD be created only when absent or empty (`install -o nobody` + `if [ ! -s ... ]`), never overwriting user code.
- Manifests adding apt sources MUST run `apt-get update -qq` before installs (issue #79 fix).
