Catalog of Infinite OS service manifests. Each category subdirectory holds installable services; a service is a directory with a `manifest.{json,yml,yaml}` plus an optional `assets/` directory. Infinite OS fetches manifests from repository branches (which act as releases) and executes them on target hosts.

## Summary

- database/ — Database services: MariaDB, MongoDB, OpenSearch, PostgreSQL, Redis
- other/ — Miscellaneous services: Hermes Agent, OpenSSH, Supabase Vector, Vector
- runtime/ — Language runtimes: Bun, Java, Node, PHP WebServer (OpenLiteSpeed), Python, Ruby
- system/ — Core system services (Cron, Nginx, OS API); avatar-only, no manifests — managed by Infinite OS itself
- webserver/ — Web server services: Kong API gateway
- .github/workflows/ci-services.yml — nightly CI that installs every catalog service/version inside a `goinfinite/os` Docker container and reports PASS/FAIL/SKIP
- README.md — Manifest schema, placeholder reference, branch-based versioning table, `assets/` conventions
- CHANGELOG.md — Version history of the services catalog
- CONTRIBUTING.md — Contribution, licensing (EPL-2.0 + FLA), and PR guidelines
- LICENSE.md — Project license
- AGENTS.md — (untracked) agent-harness style book; harness files live in `.agents/`
- opencode.json / .ignore — (untracked, gitignored) opencode agent config and tool ignore rules

## Constraints

- MUST NOT modify `.agents/` directory — managed externally via git.
- Each installable service MUST have a manifest file (`.json`, `.yml`, or `.yaml`) conforming to the schema in README.md (`manifestVersion: v1`).
- Manifest install steps MUST carry a standalone `apt-get update -qq` immediately before package installs that follow an added apt source (issue #79 fix; see CHANGELOG 2.2.0 "refresh apt index after adding repository").
- Services CI matrix MUST stay under 256 entries (GitHub Actions limit; issue #80 open) — adding many versions to one manifest grows the matrix.
- Version branches (`v0`, `v1`, `v2`) are the release mechanism; `v2` targets Infinite OS >= v0.3.3 with `manifestVersion: v1` (README mapping).

## Guidance

- Service directories SHOULD include `assets/avatar.jpg` (or `.png`); `avatarUrl` points at the published GitHub Pages path of that asset.
- Shared install logic SHOULD live in `assets/*.sh` invoked via `%installableServiceAssetsDirPath%` rather than inlined in the manifest (see runtime/php-webserver).
